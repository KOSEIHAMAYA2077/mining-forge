# 小さなインディーゲームとして完成させる順序

更新日：2026-09-06。日付や工数の約束ではなく、判断の区切り。実装とプレイ結果に応じて改訂する。

| 段階 | 成果物 | 次へ進む条件 |
| --- | --- | --- |
| M0 企画と保存基盤 | 現在仕様、開発メモ、試作仕様、GitHub、作業記録 | 読み手が現在地と次の一件を特定できる |
| M1 P0a 採取一回 | 結晶1個、3ゲージ、技、会心、回収、基本演出と音 | 加減の判断が理解でき、致命的な計算不具合がない |
| M2 P0b 3系統の循環 | 3系統各1種、工房、道具・遺物・マナ、保存、Windowsビルド | 一往復を通せ、成長後に選ぶ手が変わる |
| M3 P1 遠征の判断 | 小さな分岐、帰還の制約を1案だけ比較 | 続行と帰還の判断が面白い、または制約を外す理由を確認できる |
| M4 完成版の内容を固定 | 舞台1つ、少数の区域・採集物・成長、最終目標 | 内容を増やす作業を終え、開始から結末まで通る |
| M5 仕上げと配布準備 | 操作説明、音量・表示調整、セーブ安定性、配布ビルド | 別環境で開始から終了まで確認でき、既知の重大不具合がない |

P0を作る段階ではM3以降の基盤を先取りしない。P0aだけで作品完成とせず、ユーザーが求めた3系統の循環までP0bでつなぐ。

## 最初の完成版に置く上限案

以下は膨張を止める上限で、すべてを作る約束ではない。

- プラットフォーム：Windows、ローカル一人用。
- 拠点1つ、舞台テーマ1つ、小さな区域3つまで。
- 採集物は3系統合計9種類まで。対象差は既存操作の組み合わせを優先。
- 装備アーティファクト6個まで、装備枠2まで。
- 基本4技＋解放する派生技5個まで。習得ツリーは小さくする。
- 道具部品6個まで。品質ごとに大量の固有装備を生成しない。
- 主目標1本と明確な到達点。初回1〜3時間程度を仮の目安とし、実測で見直す。
- NPC大量会話、オンライン、自由な地形掘削、空船操縦、別系統の戦闘は完成版の初期上限にも含めない。

## 増やす前に確認すること

新しい要素は「既存のどの判断が変わるか」「制作と検証がどれだけ増えるか」「代わりに何を削るか」をIssueに書く。答えが世界の広さや数の多さだけなら保留する。

P0で手の選択が面白くない場合は、適正帯・効果範囲・技の消費・品質の伝え方を直す。対象種類を増やして解決したことにしない。

撤退制約を足した結果、気持ちよく採る時間が減るだけなら、P1で不採用にしてよい。ローグライト化を完成の必須条件にしない。

## 終了判定

最終目標まで到達でき、帰還と成長に詰みがなく、保存・再開が安定し、見た目・音・操作の最低品質を満たしたら、内容追加を止める。Steamでの公開、価格設定、ストア素材、外部への配布は、その段階で別の依頼として具体化する。
