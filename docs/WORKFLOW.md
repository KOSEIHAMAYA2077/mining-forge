# GitHub・進捗・作業メモの運用

更新日：2026-09-06

## 正本

共有の正本はGitHubリポジトリの `main`。作業中のコードは機能ブランチに置き、設計の現在地は `MASTER.md` と `STATUS.md` で示す。Issueや会話だけで新しい仕様を確定したことにせず、採用した変更は該当する設計文書へ反映する。

リポジトリ名は `mining-forge`（開発用の仮称）。公開する依頼はまだないため、初期設定は非公開。販売名と一致させる必要はない。

## 毎回の作業

ユーザーのプレイを挟んだ往復は [PLAYTEST_LOOP](PLAYTEST_LOOP.md) を参照。実装担当の報告と感想を受け、設計担当が変更仕様へ整理し、GitHub経由で実装担当へ戻す。

1. 開始時にGitの状態と未コミット変更を確認する。クリーンな場合に最新の共有状態を取り込む。変更がある場合は勝手に破棄しない。
2. `START_HERE`、`MASTER`、`STATUS`、`handoff/CURRENT` を読み、今回の依頼・Issueを特定する。
3. 一件の目的に絞って作業する。機能実装は `feat/短い目的`、不具合修正は `fix/短い目的` などのブランチを使う。文書だけの小変更はmainでよい。
4. 変更に適した確認を行う。ゲーム実行、計算検証、目視確認、文書リンク確認など、実際に行った確認を区別する。
5. `STATUS` と `handoff/CURRENT` を更新し、日付付きセッションメモを追加する。新しい設計判断があるときは `DECISIONS` と現在仕様も更新する。
6. 差分を読み、必要なファイルだけをステージしてコミットする。認証情報や生成物が含まれていないことを確認してpushする。
7. 機能ブランチはPRに目的・結果・検証をまとめる。統合はユーザーの指示に従う。Issueは完了条件を満たしてから閉じる。
8. リモートへの保存状況、未検証、次の作業を報告する。pushに失敗したら「GitHub保存済み」としない。

この運用は、今回依頼された「GitHubへ進捗と作業メモを残す」を日々の作業に含めるためのもの。自動で将来の作業を開始するスケジュールや通知は設定していない。

## 進捗を置く場所

| 場所 | 更新する内容 |
| --- | --- |
| `docs/STATUS.md` | 完了・作業中・未着手・実際の検証状況 |
| `docs/handoff/CURRENT.md` | 次の一件、読む資料、開始条件、注意点 |
| `docs/sessions/YYYY/MM/DD/HHmm-短い名前.md` | 今回の依頼、変更、根拠、検証、未解決、次の一手 |
| `docs/DECISIONS.md` | 採用・保留・撤回した設計判断と理由 |
| GitHub Issue | 作業単位の目的、範囲、完了条件、対応PR |
| GitHub PR | レビューできる差分と確認結果 |

本文に自分自身の最終コミットIDを書こうとしない。そのメモを保存したコミットはGit履歴で追える。確認対象となった以前のコミットID、実行したビルドID、関連Issueは必要に応じて記録する。

## 端末や担当を切り替えるとき

送り出す側は変更とセッションメモをコミットしてpushし、`handoff/CURRENT` にブランチと次の作業を書く。受け取る側はcloneまたは更新し、そのブランチを確認する。チャット履歴を再現しなくても続けられるよう、未決事項と未検証を具体的に残す。

同じ機能をMacとWindowsで同時に編集する場合はブランチを分ける。Unityの `Library` を共有せず、`Assets` と対応する `.meta`、`Packages`、`ProjectSettings` を管理する。Unityを導入した際に、実際の版を文書と `ProjectVersion.txt` で固定する。

## 実装を始めるときに記録すること

エディタの版、対象OS、起動・ビルド手順、依存パッケージ、使用素材、セーブ場所を記録する。大きなバイナリ素材を追加する前にGit LFSの要否を検討し、両端末で利用できることを確認してから設定する。現時点ではLFS、CI、ビルドの自動配布を設定していない。

## Codexの入口について

ルートに `AGENTS.md` を置き、現在仕様への読み順を明示している。Codexはプロジェクトルートから作業ディレクトリへの経路で指示ファイルを読むため、原則としてリポジトリルートを作業フォルダにする。任意の文書名が自動で読み込まれるとは想定しない。[公式のAGENTS.mdガイド](https://learn.chatgpt.com/docs/agent-configuration/agents-md)
