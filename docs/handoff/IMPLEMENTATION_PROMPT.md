このリポジトリのPrototype 0を、Unityで作ってください。まず `AGENTS.md`、`docs/MASTER.md`、`docs/STATUS.md`、`docs/handoff/CURRENT.md`、`docs/PROTOTYPE_0.md` を読み、既存の変更と開発環境を確認してください。Unityプロジェクトはリポジトリ内の `game/` に置き、実際に使うエディタの版を記録してください。

作るのは、DQ11の鍛造をモチーフに、部位・技・集中力・会心・適正ゲージから一手ずつ「ちょうどよく採る」小さな3Dゲームです。DREDGEのように、採った物を持ち帰り、次の探索の準備へつなげます。結晶は資金と道具素材、古代機械は永続解放するアーティファクト、魔力は採取技を覚えるマナになります。共通の採取操作を使い、3系統で別々のミニゲームを作らないでください。

まずP0aとして結晶1個の採取、4基本技、会心、品質、回収、打撃演出と音を完成させて確認してください。その後P0bへ進み、3系統各1種類、工房への帰還、道具部品・遺物装備・技解放、保存、再採取まで一往復を通してください。詳細は `docs/PROTOTYPE_0.md` を優先し、仮数値は調整可能にしてください。P0aだけでP0全体が完成したとは扱わないでください。

https://kenney.nl/assets から適したアセットをダウンロードして積極的に採用してください。候補は `docs/ASSETS.md` にあります。実際の使用ファイル、配布元、ライセンス、改変と使用箇所を記録してください。

見た目・エフェクト・サウンドを必須要件にします。選んだ部位へ打撃が入り、母岩が削れ、石片が飛び、ゲージと音が同期するようにしてください。会心、適正帯到達、損傷、回収品質を視覚と音で区別してください。結晶の芯、古代機構、魔力を帯びた器の違いが見えるようにし、配色、縮尺、光、UIを揃えてください。背景が空、無音、メーターだけが動く状態で完成扱いにしないでください。

現行範囲は小さな採集場と工房です。別の鍛造ミニゲーム、カード戦闘、敵AI、Voxel、オンライン、自由飛行、巨大なスキルツリー、遠征全体の全損ルールを追加せず、今回の採取と成長を完成させてください。舞台やローグライト化などの未決事項は文書に残してください。

品質と回収の境界、未加工からの無料報酬、消費不足、ノード再利用、二重帰還、カバン満杯、売却と素材化の排他、永続解放、補給品の消費、保存・再起動を確認してください。日本語表示、1280×720と1920×1080、音量と画面揺れの調整も確認してください。実行環境が足りない場合は、実装済みと未検証を区別してください。

作業は意味のある単位でコミットし、既定のGitHubリポジトリの作業ブランチへpushしてください。実装のPRには結果と検証を記録し、`docs/STATUS.md`、`docs/handoff/CURRENT.md`、当日のセッションメモを更新してください。ソース、Windowsビルドの場所、起動・操作説明、使用素材、確認結果、残件を報告してください。

判断したいのは「一手を選ぶのが楽しいか」「採集物ごとに欲しい理由が変わるか」「持ち帰って得た道具・遺物・技で、もう一度採りたくなるか」です。
