## 現行画面の問題

保存された実画面 `docs/verification/P0a-02/01b-skills-1280.png` を確認。細かい灰色の母岩が広く主役を覆い、結晶の輪郭・透け方・光を鑑賞できない。矩形の情報領域と説明が同じ強さで並び、対象→狙う位置→使う技への視線移動が難しい。Kenney素材の導入や画面チェックの合格は、この表現がユーザーに好まれたことを意味しない。

主役の絵、部位表示、コマンド階層、打撃から結果までの演出を一体で作り直す。背景の素材を交換するだけでは完了しない。

## 画面の指定

基準1920×1080、1280×720でも判読できること。1画面の固定カメラでよい。2D操作面に3D結晶を配置する方法も可能で、探索用3D空間を作る必要はない。

| 領域 | 配置目安 | 表示するもの |
| --- | --- | --- |
| 左のコマンド | 横幅約22%、上から12〜48% | たたく／特技／詳しく見る／採取する。選択は文字・枠・背景の明度で分かる |
| 左の補足 | 同じ幅、48〜87% | 選択した技の名前、効果、範囲図、集中力と消費。特技一覧は特技を開いた間だけ表示 |
| 主役 | 中央〜右、横方向44〜80%、縦方向14〜85%を目安 | 一つの連続した大きな結晶。初期状態でも輪郭と内部の光が分かる。母岩は周辺と根元中心 |
| 部位ゲージ | 結晶の左右、対応する部位の高さ | 現在値・適正帯・中心・選択時の到達予測。線の交差を避ける。細かい数値は選択時または詳細画面へ |
| 上部 | 高さ10%以内 | 対象名、活性。大きい装飾バーで主役を圧迫しない |
| 下部 | 高さ8%以内 | 現在必要な操作だけ。実際に使えるマウス・キーボード操作を表示 |

文字は実UIで描画する。基本文字は1920基準28px程度、主要コマンド36px程度から調整し、縮小後も読めるか確認する。背景と文字のコントラストを取る。シード、開発者向け状態一覧、常時の長文説明を通常画面へ並べない。

**画像見本の2列×3行は構図の例。ゲーム盤面を長方形6マスへ変更する指示ではない。** 現行2列×4行中6マスの欠けた形をまず維持し、その形の下に連続した結晶を置く。各マスへ同じ石を敷き詰めない。マス数を6に固定する将来制約も設けない。

非選択の境界は控えめに、選択した作用範囲だけ強調する。現行の通常／会心の到達予測・消費・無効理由を保持し、見本に省略されているから削除しない。通常は操作に必要な情報へ絞り、詳しく見るで全数値を確認できる。

## 結晶の作り方と素材

最短の実装案は同梱Lucentパッケージのメッシュを使い、前作の「透ける外殻・稜線・内部コア」を現在のURPで再構成すること。細長いPrismを主結晶に、短い副結晶を数本組み合わせ、一つの標本として読む輪郭を作る。元モデルと同じ色を一面に塗るだけでは足りない。旧パッケージはBuilt-in用のためURPでの材質変換・表示検証が必要。

静止画を使う場合は背景と対象と母岩を別レイヤーにする。今回の生成画像のうち、画面見本は一枚絵、結晶単体の習作は市松模様が焼き込まれたRGB画像で、透過スプライトではない。どちらも、そのまま操作面や透過素材として取り込まない。市松模様を表示する状態では完成扱いにしない。

Kenneyは適合する岩・粒子・音に引き続き使用できる。高精細な結晶の横に拡大した低解像度タイルをそのまま置かず、画面全体の粒度を揃える。DQのスクリーンショットやUI装飾を素材として切り抜かない。

## 打撃と状態の表示

- 選択：作用する部位とゲージが同時に強調される。色だけでなく枠と範囲図でも示す。
- 通常打撃：打点に道具→短い停止→小さな石片と局所の発光→対応ゲージが移動。すべての部位を同時に揺らさない。
- 範囲打撃：実際に当たった部位を見分けられる。複数セルを一枚の全面フラッシュで隠さない。
- 適正帯／中心：帯入りと中心一致を見分けられる表示。中心一致の現行得点上の利点はないため、専用表示だけで「追加ボーナス」と説明しない。
- 過打／破損：打った位置に亀裂・欠け。損傷していない場所の見た目まで壊さない。破損後続行という既存ルールを保持。
- 採取：対象をきれいに見せる結果画面。品質、得られた物、未分離で報酬なしの場合の理由を短く表示。

母岩除去で対象が分かるようにする一方、開始画面から鑑賞できる結晶を残す。「操作するまで魅力が見えない」初期状態に戻さない。音は既存素材を土台に、削り・強打・会心・損傷を聞き分けられるようにする。音声出力の存在だけでは聴感検証にならない。

## 実装と確認の区切り

1. 新しい表示を既存のBoardSessionへ接続する。採取計算と報酬処理を見た目変更のために書き直さない。
2. 開始・特技選択・範囲予測・打撃後・途中評価・破損・回収結果を実アプリで確認する。開始画面だけの見栄えで終えない。
3. 1280×720と1920×1080で文字、対応線、ゲージ、押せる領域、長い技名の重なりを確認。キーボードとマウス双方で採取完了まで操作する。
4. 表示変更が判定・二重入力・報酬に影響していないことを既存の適切な検証で確認。新規の見た目テストを大量に増やす必要はない。
5. 実画面の比較画像と短い操作録画を保存し、聴いた音と聴いていない音を区別する。新ビルド名・ソース・PR・実起動場所をPLAYTEST_LOOPに従って報告する。

改修案では表示を先に比較し、DQ11との数値・特殊効果の差分を同時に無断調整しない。特に「中心へ近いほど品質が上がる」「会心を狙う技」「活性の節目効果」は次のルール改修候補として別途扱う。この順序は担当者の切り分けであり、ユーザーが完全再現を不要と言ったわけではない。
