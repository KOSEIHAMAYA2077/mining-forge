# 現在の企画の正本

更新日：2026-09-06。仮称：Mining Forge。状態：P0a-01の初回感想を受領、変更案の設計相談（`feat/p0a-crystal`）。

## 一文のコンセプト

**未知の採集物を傷つけずに取り出す採取職人となり、結晶で道具を作り、遺物で採り方を変え、魔力で技を覚えて、次の探索へ向かう。**

## ユーザーの方針として採用したこと

- 小さなインディーゲームとして完成させることを目指す。
- DQ11の鍛造をモチーフに、技・会心・適正ゲージを使う「ちょうどよく採る」操作を中心に検討する。
- 結晶、化石・古代機械、魔力を排他的な題材にせず、同じゲームで別々の役割を持たせる。
- 結晶は金銭・素材、化石や古代機械はアーティファクトによる恒久効果、魔力はスキルを伸ばすマナにつなげる。
- DREDGE、Space Order Mineは近い参照例。世界観はまだ決めない。
- Kenneyの素材を積極的に使い、見た目・エフェクト・音を試作から重視する。
- 設計、進捗、作業メモをGitHubに保存し、実装担当へ引き継げる状態にする。
- 追加依頼によりP0aを実装し、結晶1個の操作感をユーザーが遊ぶ区切りを作る。P0bへ自動的には進めない。
- 初回感想：基本の仕組みは良い。技の使い分けの少なさと簡素な見た目を改善したい。次はマスの位置・目標値・技の範囲が意味を持つ盤面を検討する。
- 表現は3D必須ではない。Roguelike Caves & Dungeonsのような2Dを第一候補として検討。Kenney以外の音・フリー3D素材も個別の利用条件を確認して候補にできる。
- 盤面・状態変化・2D化の一括実装はしない。今回はプレイメモと検討案の保存まで。状態による効果量変化は候補、持ち込みスキルセットは将来案。

## 小さく作るための設計提案

以下は担当者の提案であり、ユーザーが全項目を確定したという意味ではない。試作の入力として使い、結果から改訂する。

- **採取の計算と基本操作は1系統。** 対象ごとに適正帯、演出、持ち帰る報酬を変える。
- 持ち帰った後の加工は、まずレシピ選択にする。採取と別の本格鍛造ミニゲームを同時に作らない。
- アーティファクトは取得履歴と効果の解放を永続化し、効果を装備枠で選ぶ。無制限に全効果を積み上げるかは保留。
- スキルの解放は永続化する。道具・遺物・技が採取の別の部分を変えるようにする。
- 最初の試作は「3系統を各1種類、道具部品1個、遺物効果1個、解放スキル1個」。新しい題材ごとに別ゲームを作らない。
- P0は安全な帰還と小さなカバンで循環を確認する。遠征全体の失敗条件はP1で比較する。
- P0aの開発環境はUnity 6000.3.18f1・C#・URP 17.3.0、Windows x64向け一人用。

## コアループ

準備 → 採集対象を探して選ぶ → 部位と技を選び加減して採る → カバンの中身を選ぶ → 帰還して確定 → 製作・遺物装備・スキル解放 → 新しい選択肢で再探索。

品質の役割は「手間をかける意味」を作ること。高品質が必須で進行が止まる設計にはしない。

## まだ決めないこと

- 地下、空島、遺跡などの舞台。船の操縦や地形破壊の採用も未決定で、現行試作には含めない。
- 遠征の制約を行動力・時間・道具耐久・環境危険のどれにするか。
- 撤退が単なる持ち帰り判断か、帰路を含めた危険な判断か。
- 強制帰還で失う物と残す物。ローグライトと呼ぶほどラン単位の変化を入れるか。
- カバンの形状パズル、カード表示、複雑なスキルツリーの採用。
- 最終販売価格、販売日、製品名、最終コンテンツ量。

「採取一回の失敗」「自発的な帰還」「遠征全体の失敗」は別々に検証する。カバンが満杯になっただけで死亡・全損にはしない案を基準にする。
